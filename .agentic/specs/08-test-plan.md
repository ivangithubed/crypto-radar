## 2. Підхід

- **Піраміда:** модульні й інтеграційні тести — етап 7 (Vitest, 91 тест оракула етапу 6 на jsdom); E2E і axe в наборі — етап 8.b; **цей етап** — рівень «користувач + система цілком» у справжньому Chromium: ручні й дослідницькі сесії та одноразові сценарії керованих станів.
- **Два режими даних:**
  1. **Живий CoinGecko** у вбудованому браузері (Chromium) через `vite preview` — «щасливі шляхи», клавіатура, 320 px, теми, справжні відповіді 429.
  2. **Керовані стани** — одноразовий сценарій Playwright `.agentic/qa/runs/support/qa8a.mjs` і `qa8a-extra.mjs` (підміна `api.coingecko.com` записаною фікстурою `src/test/fixtures/markets-top50.json`, `page.clock` для меж свіжості). Тестовий проєкт не створюється (це етап 8.b).
- **Обмеження підміни:** `route.fulfill` Playwright **не відтворює** блокування CORS (відповідь без `Access-Control-Allow-Origin` браузер усе одно читає). Тому сценарій «429 без CORS» перевіряється лише на живому CoinGecko і через аналог «мережевий збій при `navigator.onLine === true`» (`route.abort`).
- **Пріоритет за ризиком:** MoSCoW етапу 2 × імовірність збою. Найвищий ризик — US-8 (guardrail M-5: жодних неправильних цін) і NFR-3 (ліміт CoinGecko без ключа, ризик підтверджено на гейті 7).
- **Техніки:** класи еквівалентності (пошукові запити, джерела помилок E-*), граничні значення (25/50 монет, 0/1/49/50 обраних, 0/1/50/51 символ, межа свіжості 299/300/301 с, округлення ±0,04/±0,05/±0,06 %, місця 49/50/51), таблиці рішень (джерело помилки × мережа → текст і кількість запитів), переходи станів (Loading → Data → Error → Data; В обраних ↔ Поза топ-50), дослідницькі сесії за чартерами.

## 4. Критерії входу й виходу

**Вхід:** етап 7 схвалено (`APPROVED_AND_COMMITTED`, `8645c76`); збірка зелена; preview відповідає 200; TC пройшли рев'ю власника (на гейті 8.a).

**Вихід:**

- виконано 100 % TC пріоритету Must, які може виконати агент; TC «виконав: власник продукту» мають результат від власника або явне рішення відкласти їх;
- немає відкритих BUG із Severity Blocker / Critical;
- кожен відкритий Major має рішення власника (виправити зараз — запит на зміну; або відомий дефект);
- axe: 0 порушень `critical` / `serious` (`pnpm test:a11y`).

## 5. Ризики

| Ризик | Тип | Реакція |
| :--- | :--- | :--- |
| CoinGecko відповідає 429 без CORS → застосунок бачить мережеву помилку (підтверджено 2026-11-03 04:19 і 04:52) | Продуктовий (NFR-3, US-8) | TC-061, TC-062; BUG-001 |
| Нестабільний живий CoinGecko (429) під час ручних сесій | Проєктний | Паузи; керовані стани на фікстурі; живий 429 використано як доказ |
| Підміна Playwright не відтворює CORS | Проєктний (хибна впевненість тестів) | Окремий живий доказ; рекомендація для 8.b — проксі без CORS-заголовка або `route.abort` як аналог |
| Монета з `null` у полі CoinGecko (нові лістинги) ламає весь знімок | Продуктовий (доступність продукту) | TC-086; BUG-003 |
| Втрата обраних (Safari ITP, приватний режим) | Продуктовий (US-6, ADR 0006) | TC-084 (E-STORE), TC-088 (Safari — власник) |
| Немає Safari / Firefox / зчитувача в середовищі агента | Проєктний | Чек-лист власника; результат — з позначкою «виконав: власник продукту» |
