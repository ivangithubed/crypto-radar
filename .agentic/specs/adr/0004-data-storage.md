# Сховище: лише localStorage браузера для обраних і теми, без серверної бази

## Context and Problem Statement

Обрані монети й вибір теми мають зберігатися на пристрої відвідувача без акаунта, щонайменше тижнями (US-5, US-6, US-10; бриф §10). Ринкові дані беруться з CoinGecko й не повинні кешуватися довше, ніж потрібно для показу (умови API CoinGecko §6.1, guardrail M-5). Серверу в продукті немає (ADR 0001), тож `stack.database` дорівнює `null`. Цей ADR фіксує сховище браузера, бо продукт усе ж зберігає дані на пристрої.

## Decision Drivers

- US-5 / US-6: обрані без акаунта на пристрої; US-10: тема запам'ятовується.
- NFR-10: лише ідентифікатори обраних і тема, без персональних даних; NFR-11: продукт сам не видаляє обрані.
- Умови CoinGecko §6.1: дані не кешуються довше 24 год; M-5: застарілі ціни не показуються.
- Простота для початківця.

## Considered Options

1. **localStorage** — синхронний API ключ-значення, рядки JSON.
2. **IndexedDB** — асинхронна база в браузері (наприклад, через обгортку-пакет).
3. **Серверне сховище з анонімним ідентифікатором пристрою** — синхронізація в майбутньому, але потрібні сервер і персональні дані.

## Decision Outcome

Обрано **варіант 1 «localStorage»**. Даних мало (≤ 50 ідентифікаторів і одне значення теми), і синхронного API досить. IndexedDB додає асинхронність і, можливо, залежність без вигоди. Обмеження Safari (7 днів без взаємодії) однаково стосується обох варіантів (ADR 0006). Варіант 3 суперечить ADR 0001 і бюджету.

- **Ключі:**
  - `crypto-radar:favorites` — JSON-масив унікальних рядків-ідентифікаторів CoinGecko, наприклад `["bitcoin","ethereum"]`;
  - `crypto-radar:theme` — `"light"` або `"dark"`; відсутність ключа означає «як на пристрої» (`prefers-color-scheme`);
  - `crypto-radar:safari-hint-dismissed` — `"1"`, якщо відвідувач закрив підказку Safari (ADR 0006).

  Інших ключів немає (NFR-10).
- **Ринкові дані** в localStorage не пишуться: вони живуть лише в пам'яті вкладки (кеш TanStack Query) і зникають після її закриття.
- **Цілісність:** під час читання перевіряється формат; некоректне значення дає порожній список або тему за замовчуванням без падіння; дублікати прибираються. Доступ до localStorage загорнутий у `try/catch`: у приватному режимі чи при вимкненому сховищі обрані працюють у пам'яті до кінця сесії, а відвідувач бачить повідомлення про це (текст — етап 4).
- **Кілька вкладок:** подія `storage` оновлює обрані в інших вкладках того самого браузера; остання дія перемагає. Оптимістичне блокування за `version` не застосовне: спільних об'єктів немає.
- **Міграції формату:** forward-only. Зміна формату означає новий ключ (наприклад, `crypto-radar:favorites:v2`) і одноразове перенесення зі старого ключа під час читання (схема expand → migrate → contract у браузері).
- **Резервні копії і RPO:** не застосовно, бо дані живуть лише на пристрої відвідувача; втрата при очищенні браузера — прийнятий наслідок (US-5 правило 6).
- **Строк зберігання й видалення:** продукт сам нічого не видаляє за часом. Відвідувач видаляє дані, прибравши монети з обраних або очистивши дані сайту в браузері. Персональних даних у сховищі немає (NFR-10).

### Consequences

- Добре: без залежностей, синхронно, просто тестувати (jsdom має localStorage).
- Погано: Safari видаляє дані сайту через 7 днів без взаємодії (ADR 0006); дані не переносяться між пристроями (A-4).
- Нейтрально: ліміт localStorage (порядку мегабайтів на сайт) значно більший за потреби (менше 2 КБ).

### Confirmation

- Етап 7: модульні тести `favorites` і `theme` — додавання, прибирання, без дублікатів, некоректне значення, недоступне сховище, подія `storage`.
- Етап 8.b: E2E перевіряє, що після перезавантаження обрані й тема зберігаються (AC-6.1, AC-10.2), а в localStorage немає цін (NFR-10).
